# 작업 수명주기 스킬과 붙이기

이 스킬은 단독으로 완결되지만, 티켓 단위 런북·QA·리포트를 관리하는 스킬(예: `/task`)이 있으면 **작업 하나 = 작업 보드 하나**로 붙인다.
런북은 따로 아티팩트를 만들지 않고 작업 보드의 「런북」 탭으로 게시한다 — 상태는 진행 탭, 서사는 런북 탭이 정본이다.
아래는 그 스킬 쪽에 넣을 지시문의 예다(경로·문서 이름은 그쪽 규약을 따른다).

| 시점 | 부르는 것 | 런북 쪽 |
|---|---|---|
| 킥오프 | `/board new <티켓 제목> --file <런북 디렉터리>/board.json --repo <리포> --ticket <키>` → `/board runbook <런북 디렉터리>/runbook.html` | 런북 파일은 로컬에 만든다. 상황판·매트릭스·「내가 할 일」 절을 두지 않는다 |
| 갱신 | 런북 파일 편집 → `/board sync` → `/board runbook …` | 결정·이어받기 항목을 쓰면 관련 카드 `links`에 `#runbook/<절id>-N`을 넣는다 |
| 마무리(wrap) | `/board sync`·`/board runbook` 마지막 1회 → 아티팩트 제목을 `🗄️ 보관 \| 작업 보드 · <제목>`으로 재게시(같은 URL, `icon` `archive`) | 결론 이관(Jira·Confluence)의 원천은 런북 탭이다 |

- 런북의 "이어받기·사람 몫·결정 대기·외부" 같은 **서사형 목록은 런북에 남긴다** — 카드 필드로 담기지 않는 커밋 순서·조건이 거기 있다.
  대신 같은 사실(단계·막힘·담당)을 런북에 다시 쓰지 않는다. 그것은 카드가 보여준다.
- 기존 런북에 매트릭스가 있으면 `/board import`로 옮긴 뒤 매트릭스 절을 지우고 `/board runbook`으로 게시한다.
- 따로 게시돼 있던 옛 런북 아티팩트는 보관 전환하고(`🗄️ 보관 \| 런북 · …`) 맨 위 띠에 작업 보드 URL을 적는다.
- `board.json`·`runbook.publish.json`은 런북 파일과 같은 디렉터리에 둔다. 그 디렉터리가 git에서 무시되면(`.task-docs/`) 이 파일들은 로컬 백업일 뿐이다.
